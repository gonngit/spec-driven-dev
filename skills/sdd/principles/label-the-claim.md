# Label the claim

For every fact in the journal, a review note or a report, say how you know it. An assumption does not weigh the same as a verified fact.

**Why:** Assumptions turn out wrong. Without a label an assumption reads as a fact, and decisions pile up on it.

**How:**
- There are four labels. **verified** (확인): you ran it and saw it. **read** (읽음): you read the code or a document and did not run it. **assumed** (추정): you did not verify it. **question** (질문): it is for the user to decide.
- Attach the method to "verified" ("verified by running it", "verified by injecting a defect").
- Mark a fact that comes from memory "from memory, not verified" (Korean "기억, 검증 안 함").
- Count a number that goes into a document with a command. Do not write it from memory.
- Turn cheap assumptions into verified facts. Leave the ones you could not turn under "Open" in the report.
- If you later learn that something was wrong, do not delete the earlier record. In a new step, under Observations, write `wrong: <date> step N` (Korean `틀림: <날짜> 스텝 N`) and the correct fact.

**Stop:** Do not write an unlabelled "probably" or "it is likely" in documents or reports.

**Evidence:** The review-note table has a "Kind" column.
