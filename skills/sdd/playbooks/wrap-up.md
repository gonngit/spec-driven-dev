### Wrap-up

**You own the record of the step.** Do it at the end of every playbook. Start from playbook step 1 even when only a commit was requested.

Bring the record in line with the rules. "A simple step with no decision" is still a step.

1. Read `git status --short -- .` and `git diff --stat -- .`. Look for untracked files you did not create, files that do not belong to this step, and defects that were not restored. Remove leftovers: scratch copies and what a test run leaves (`__pycache__/`); do not add ignore files without asking. List changes outside the project and ask about them; record each under this project's journal Done with its path, and commit it separately.
2. Write the journal (`references/journal-format.md`). Write it before the commit. Uncommitted steps are committed together unless the user asks otherwise. A step that rewrites commits puts its own entry into the commit it produces. A push-only step's entry goes into the next commit on the branch that will hold it. Each merge is its own step, and its entry goes into the merge commit: `git merge --no-ff --no-commit`, write and stage the entry, then commit. If the default branch is checked out nowhere and switching is blocked, add a worktree for it (`git worktree add <dir> <default branch>`) and merge there.
3. Run `scripts/sdd-check.py journal`.
4. Write the report (`references/report-template.md`).
5. If no commit, push or merge was requested, go to playbook step 8.
6. If a commit was requested, run the commands the repository rules require before a commit, then commit. Stage files by path. Ask before including untracked files you did not create. Do not commit explanation documents (`explanations/`). The repository's existing rules (rules files, CONTRIBUTING) come first for the message; otherwise write it in the project's document language (`references/doc-style.md`). Trailers the harness adds follow the same rules; if the rules say nothing, keep them and name them in the report. A commit with a failing check names the failure in the message and the journal. Rewrites follow `SKILL.md`, Autonomy. To undo a commit, make a new commit that restores only the files outside `docs/journal/`.
7. Push or merge only when asked. Pushed history is never rewritten (`SKILL.md`, Autonomy). Before merging a branch, commit its uncommitted steps on it; the merge request covers that commit. When the user asks for a local merge, merge locally as step 2 says (`--no-ff`, so the slice stays visible). The PR description is only for a hosted PR: give it in the report, and the user opens or merges the PR. Push the default branch, or delete branches and worktrees, only when asked. Verify with `git` directly: `git status -sb`, `git ls-remote`, and `git rev-parse` after a local merge.
8. Stop. Name the candidate for the next step in one line, the last line. Do not start it (`principles/user-drives-the-pace.md`). When the last task of a slice is done, the candidates are pushing the slice branch and opening a pull request, or, with no remote, a local merge asked like a push. With stacked branches, merge only the top branch: it carries the lower ones, in one merge step (`references/doc-templates.md`).

**Report:** the format of `references/report-template.md`. If you committed, one line per commit on its content, plus the files left out and why.
